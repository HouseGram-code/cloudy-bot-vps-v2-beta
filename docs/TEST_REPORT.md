# Проверки сборки — Cloudy VPS v1.0-dev

Дата: 2026-09-08. Среда: Python 3.13, Node.js 24, Chromium. Это отчёт об исходниках, не сертификат production-развёртывания.

## Выполнено

- Python compileall: исходники, установочные Python-скрипты и тесты проходят синтаксическую проверку.
- unittest: **48 тестов обнаружено, 46 успешно, 2 пропущено** из-за отсутствия discord.py.
- Проверены настройки и отказ при неверных/пустых значениях, ограничения ресурсов, отказ большого плана на маленьком хосте, резервирование остановленных VPS, истечение срока, расчёт метрик, отсутствие выдуманных нулей, фильтрация sshx URL, rate limit, SQLite и конкурентная защита от повторной выдачи.
- Контрактные тесты управляющей логики используют **подставной Docker-клиент**: проверка владельца, параметры контейнера, отсутствие передачи секретов/host mounts, отказ неподдерживаемой quota, красный статус при ошибке Docker. Это не запуск настоящего контейнера.
- `bash -n`: все установочные shell-скрипты синтаксически корректны.
- `node --check`: Freestyle bootstrap синтаксически корректен.
- Дополнительный поиск явных секретов в распространяемых файлах: совпадений нет. Это не полноценный secret scanner и не гарантия отсутствия всех классов секретов.
- HTML preview просмотрен после рендеринга на 1100px и 390px; состояния normal/high load/incident проверены визуально. Он подписан как демонстрационный, не выдаётся за настоящий Discord или live-метрики. Перекрытий/горизонтального выхода за экран в проверенных видах не обнаружено.

## Не проверено в этой среде

Здесь нет Docker daemon/CLI и нет сетевого доступа для установки отсутствующих зависимостей. Не использовались аккаунты, токены или API-ключи пользователя.

- Полный Docker build Ubuntu + sshx, работа XFS loop mount/project quota, cgroups и firewall на целевой VM.
- Реальное подключение Discord, privileged intent, доставка DMs, callbacks/buttons после reconnect и интерактивная sshx-сессия.
- Два теста с установленным discord.py (размеры embeds/persistent views и регистрация команд) пропущены. CI запустит их после установки зависимостей.
- Freestyle API, права аккаунта, доступность выбранного размера, persistent/always-on настройки, биллинг и фактическая установка на VM.
- Полный Ruff lint и GitHub Actions не запускались здесь. Workflow приложен для проверки после загрузки в ваш репозиторий.
- Независимый security-аудит, нагрузочное тестирование, защита от враждебных публичных арендаторов и гарантия uptime.

## Обязательный live-check на вашем хосте

1. Использовать свежие секреты, закрытую роль тестировщика и отдельную свежую VM. Проверить тариф, бюджет и разрешение провайдера на такой сценарий.
2. Завершить install.sh, выполнить doctor.py; проверить, что Docker действительно использует overlay2/XFS/pquota, а квоты подтверждаются Docker inspect.
3. Проверить firewall: гостю недоступны host/private/metadata адреса и другие контейнеры; HTTP/HTTPS и заданный DNS работают. Не сканировать чужие сети.
4. Создать один тестовый контейнер через `$deploy`; `$manage` должен показывать настоящий статус/uptime/квоты. Убедиться, что повторная выдача запрещена.
5. Попробовать чужие кнопки со второго тестового Discord-аккаунта — доступа быть не должно.
6. Проверить Start/Stop и сохранение тестового файла; Reinstall — только после явного подтверждения и резервной копии. Убедиться, что файл действительно удаляется, а срок не продлевается.
7. Проверить sshx при закрытых DMs: публичной ссылки нет и новый сеанс не создаётся. При открытых DMs ссылка приходит только в личку; повторный sshx закрывает старый сеанс.
8. На отдельном тестовом контейнере проверить остановку по истечении срока даже при выключенном Discord-боте. Не менять labels действующих пользовательских контейнеров без согласованного обслуживания.
9. Перезапустить бот: кнопки и SQLite-состояние сохраняются. Перезапустить хост: mount/firewall/таймеры возвращаются, гости не стартуют автоматически.
10. Настроить внешний мониторинг, приватные backups, лимиты расходов и процедуру удаления VM. Только затем приглашать доверенных тестировщиков.

Никакого обещания «работает бесплатно навсегда» или «production-ready» этот отчёт не даёт.
