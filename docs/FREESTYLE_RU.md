# Размещение на Freestyle

Проверка официальной документации: **8 сентября 2026**. Тарифы и интерфейс могут измениться.
Источники: https://www.freestyle.sh/docs/vms/pricing-and-limits и
https://www.freestyle.sh/docs/guides/run-docker-in-a-sandbox .

## Что реально возможно

Freestyle документирует полноценные Linux VM с root, systemd, cgroups v2 и Docker.
Используй **VM**, не обычный Web Deployment и не Dev Server с автоматическим тайм-аутом.
Бот подключается к Discord исходящим WebSocket; публичный HTTP endpoint ему не нужен.

В документации Free ограничен **8 GiB памяти и 32 GB диска на VM**.
Запрошенный гостевой план **15 GiB / 3 vCPU / 75 GiB** там не поместится даже без накладных расходов.
Пример хоста в bootstrap: **4 vCPU / 20 GiB / 128 GiB** — проверь, что твой оплаченный план разрешает такие размеры.
Не рассчитывай, что маленькие VM можно тайно объединить в один огромный Docker-хост.

Платформа учитывает **выделенные** vCPU/RAM/диск, а не только активность программы.
Поэтому тихий бот и остановленный вложенный контейнер не отменяют оплату работающей внешней VM.
По исчерпании Free allowances VM могут быть приостановлены; нет гарантии «бесплатно навсегда».
`idleTimeoutSeconds: null` — документированная настройка always-on, а не обход квот; используй её только если тариф и бюджет это разрешают.

## Вариант A — вручную, с просмотром каждого шага

1. В https://dash.freestyle.sh/ создай разрешённую **новую выделенную VM** подходящего размера.
   Не изменяй существующую VM с данными. Проверь тариф/лимиты и расходы.
2. Убедись, что VM persistent по текущей конфигурации аккаунта и не будет автоматически удалена.
   Если в интерфейсе нет этих настроек, используй официальный SDK или поддержку; не подбирай скрытые параметры.
3. Зайди в терминал VM через штатные возможности Freestyle. Проверь `docker info` и `systemctl --version`.
4. Загрузи исходники в `/opt/cloudy-vps`. Можно клонировать собственный GitHub-репозиторий, где **нет секретов**.
   Реальный `.env` создай отдельно прямо на VM с `chmod 600` и новым Discord-токеном.
5. Выполни разделы 3–4 README: XFS quota storage, затем install.sh.
6. Проверь `systemctl status cloudy-vps`, `$status`, затем одну тестовую выдачу/Stop/Start/sshx.

## Вариант B — необязательный bootstrap через официальный SDK

Выполняй **на своём компьютере**, Node.js 22+. Сначала отзови раскрытый API-ключ.
В корне проекта создай приватный `.env` с новым Discord-токеном и ID, без Freestyle API-ключа.

```bash
cd deploy/freestyle
npm install
# В Bash: ввод не отображается и сам ключ не сохраняется строкой в history.
read -rsp 'New Freestyle API key: ' FREESTYLE_API_KEY; echo
export FREESTYLE_API_KEY
export FREESTYLE_ALLOW_BILLABLE_CREATE=YES
npm run create-host
unset FREESTYLE_API_KEY FREESTYLE_ALLOW_BILLABLE_CREATE
```

**YES означает согласие на создание и увеличение новой VM, возможные расходы и настройку её Docker storage.**
Скрипт создаёт одну новую VM, запрашивает размер 4/20/128, копирует текстовые исходники и твой приватный `.env`,
затем запускает установку в фоне *на этой VM*. Никаких idle-ping/keepalive-схем нет.
Freestyle API-ключ остаётся в локальной среде и в файлы VM не загружается.
ID/slug созданной VM сохраняются локально в `.freestyle-host.json`, который исключён из Git.

Если resize запрещён, скрипт пытается удалить только что созданную пустую VM.
Если установка оборвалась позже, VM сохраняется для диагностики. **Она может продолжать потреблять оплачиваемые ресурсы.**
Проверяй dashboard и удали/останови ненужную VM штатными средствами. Не повторяй создание, не проверив существующую.

Установка может занять заметное время: строится sshx и Ubuntu image.
В терминале VM:

```bash
tail -n 80 /var/log/cloudy-install.log
systemctl status cloudy-vps --no-pager
```

Надпись installation started **не означает**, что установка закончилась. Bootstrap API и полный Docker build
не были проверены в среде сборки. Если SDK/доступ изменился — воспользуйся ручным вариантом и актуальными docs.
Старый `freestyle-sandboxes` SDK намеренно не используется: скрипт следует текущим примерам пакета `freestyle`.

## Перед открытием беты

- Пройди live-проверки из TEST_REPORT.md и ограничь доступ ролью.
- Установи alerts/лимиты расходов и следи за диском, логами и сетевым трафиком.
- Проверь правила Freestyle о перепродаже/предоставлении доступа третьим лицам; если это запрещено твоим договором,
  выбери другой разрешённый хост, а не обходи ограничения.
- Храни приватный backup, а не публичный snapshot с токенами и чужими терминалами.
